# Insights and Forecasts Documentation

This document outlines the architecture, data models, and user interface functionalities for the **Insights** and **Forecasts** pages in the SpendWise application. These features provide users with AI-driven analysis of their spending habits and predictive budgeting for upcoming periods.

---

## 1. Insights Page (`/insights`)

The Insights page is designed to help users understand trends and receive budget feedback extracted directly from their spending data. It highlights anomalies and provides actionable summary observations.

### 1.1 Functionality Overview

- **AI Insights Generation**: Displays automatically generated insights based on user spending.
- **Insight Types**: Insights are categorized into two main types:
  - **Anomaly**: Highlights unusual spending patterns (e.g., a sudden spike in a specific category). Displayed with a warning indicator.
  - **Summary Observation**: General trends or positive feedback regarding the user's budget. Displayed with an info indicator.
- **Deep Dive**: Users can interact with insights by clicking the "Deep Dive" action, which prompts the AI to provide more detailed context or answer specific questions about the observation.
- **Empty States & Loading**: Displays skeleton loaders during data fetching and a friendly empty state ("The analytics engine needs more data...") if no insights have been generated yet.

### 1.2 Data Model (`InsightModel`)

The insights are stored in the `insights` MongoDB collection with the following schema:

- `userId` (String, Indexed): The owner of the insight.
- `type` (String): Categorization of the insight (e.g., 'anomaly').
- `title` (String): A brief title summarizing the insight.
- `message` (String): The detailed observation message.
- `metadata` (Object, Optional): Additional context, containing:
  - `reason`: The AI's reasoning behind the insight.
  - `evidence`: The evidence supporting the insight (e.g., 'Active', 'High Variance').
- `createdAt` / `updatedAt` (Date): Timestamps for when the insight was generated.

### 1.3 Client Integration

- The frontend fetches insights using TanStack React Query (`useQuery`) with the `dashboardAnalyticsQueryKey` and `getDashboardAnalytics` client function.

## 2. Forecasts Page (`/forecasts`)

The Forecasts page predicts future spending behavior, helping users prepare for the next month before spending pressure arrives. It pairs projections with confidence cues and risk indicators.

### 2.1 Functionality Overview

- **Key Metrics**:
  - **Projected Spend**: The predicted total spending for the upcoming period.
  - **Forecast Confidence**: A percentage indicating the model's reliability and confidence in the prediction.
  - **Potential Pressure**: Highlights specific categories (e.g., Transport, Shopping) that pose a risk of overspending.
- **Visualizations**:
  - **Forecast Chart (`ForecastProjectionChart`)**: A line/area chart comparing observed spending against the projected month-end path.
  - **Forecast Composition (`CategoryShareChart`)**: A breakdown of how the projected spend is distributed across different categories.
  - **Category-level Forecast (`CategoryComparisonChart`)**: Compares current spending to the projected totals on a per-category basis.
- **Risk Indicators**: Textual breakdowns of areas needing attention, such as categories trending above baseline or stable recurring bills.
- **Actions**: Users can manually "Adjust assumptions" or "Save forecast" for future reference.

### 2.2 Data Model (`ForecastModel`)

Forecasts are stored in the `forecasts` MongoDB collection:

- `userId` (String, Indexed): The owner of the forecast.
- `period` (String): The time period the forecast applies to (e.g., '2026-09').
- `predictedAmount` (Number): The total predicted spend for the period.
- `confidence` (Number): A score (e.g., 0 to 100) representing the model's confidence.
- `generatedAt` (Date): When the forecast was generated by the analytics engine.

### 2.3 Client Integration

- Data is fetched using TanStack React Query (`useQuery`) with the `forecastDetailsQueryKey` and `getForecastDetails` client function.
- Values are formatted using user-specific currency settings (`user?.currency`).
